# Veera — Fix

Guidance 0.4.0. Start automatically for an ordinary request to repair a defect; explicit `/veera:fix <task>` is optional. Continue in the same turn without asking for an activation command, start message or routine confirmation. Automatic entry does not enroll other sessions, expand scope or authorize publication: freeze `delivery_mode: "local-verify"` unless the user requested publication, and preserve the mode of an existing task. An inspection-only request does not authorize edits.

Use the hook bootstrap of this chat: actual `session_id`, `plugin_data`, `package_root` (PKG) and `python_executable` (PY). Carry the data directory into CLI children as `CLAUDE_PLUGIN_DATA` with `VEERA_HOST=claude` when not inherited. Missing identity blocks owned delivery; never invent an ID or fall back to a global record. On a same-task resume use `status --root TASK`, never reinit.

Choose the lane once, before `workspace`. **Small lane** for one bounded defect: unpublished, no rendered-UI evidence needed, fix expected within 12 files. Prefer it whenever the request is unattended. Everything else (publication, UI, multi-component or underspecified work with a human available) uses the **standard lane**. Ceremony scales to the fix; verification quality and causal reasoning do not.

## Small-fix lane

Everything this lane needs is on this page; read no other Veera document or Veera source. Its budget is about 20 tool calls for a one-function fix: batch independent reads in one message, read targeted line ranges (search, then read around the hit), and run only the tests that cover the change.

1. **Diagnose before binding.** Unbound hooks are no-ops, so read the issue and the code on its path in the original checkout. Reproduce with the smallest script in the project's real environment (the container or virtualenv the request names). Separate the confirmed cause from hypotheses. Then list the issue's contract: every case it names or implies, such as each example, each input class the function accepts (prime, prime-power and composite moduli; every mode flag such as `all_roots`), every validator or raise site sharing the defect, and each call site that rebuilds the same result (search the whole package: a form field wrapping a validator counts). Maintainer signals on that path belong to the contract: an xfail test, or a `NotImplementedError` raised for an input the issue's condition covers, means implement that case generally and convert the test that asserted the gap. Scope every file the list touches; nothing beyond the list.
2. **Bind and freeze in one call.** Write the contract to a temporary file outside the repository, then run `PY PKG/scripts/delivery.py workspace --root ORIGINAL --task SLUG --session-id ID --contract FILE --request TEXT --minutes 15 --hard-minutes 45` (scale to the fix; respect stricter limits). It validates the contract, creates the task worktree, saves the frozen copy to `TASK/.veera-artifacts/contract.json` and inits; the output gives TASK (`root`), OWNER_FILE (`capability_file`) and the frozen argv. On `init_error` correct that file and run `init` once with the owner options. In check argv, `{TASK_NAME}` becomes the worktree folder name and `{TASK}` its absolute path.
   `{"delivery_mode": "local-verify", "lane": "small", "scope": ["pkg/module.py", "tests/test_module.py"], "criteria": [{"id": "C1", "text": "Observable corrected behaviour", "checks": ["focused"]}], "checks": [{"id": "focused", "kind": "test", "argv": ["docker", "exec", "BOX", "bash", "-lc", "cd /work/{TASK_NAME} && PYTHONPATH=/work/{TASK_NAME} python -B -m pytest -p no:cacheprovider -q tests/test_module.py"], "count_pattern": "(\\d+) passed", "timeout_seconds": 600}]}`
   Each check runs the new regression test plus the nearest existing test module of the changed code. Count patterns: pytest `(\d+) passed`, unittest/Django `Ran (\d+) test`, sympy `bin/test` `finished: (\d+) passed`. Point `PYTHONPATH` (or the runner's own path option) at the task folder: environments often have the original checkout installed, and a check that imports it tests the wrong code. Keep checks from writing into TASK (`python -B`, pytest `-p no:cacheprovider`). Use the project's own runner when it ships one (sympy `bin/test`, Django `tests/runtests.py`); never assume pytest is installed. `workspace` refuses a check naming a test file absent from checkout and scope, and its `check_warnings` flag pytest beside a project runner: fix the check (`correct-contract`, step 6) before going on.
3. **Work only in TASK.** Source edits are refused before init and outside TASK. Use absolute paths; start every shell call with `cd "TASK" && ` followed by one command, without pipes, `;`, redirection or extra `&&` steps. A container that mounts the parent folder sees TASK beside the original (`/work/TASK_NAME`). Confirm once, with the check's prefix, that the package imports from TASK. Put scratch scripts under `TASK/.veera-artifacts/`. Do not commit or set a Git identity: the change stays uncommitted in TASK.
4. **Fail first, then fix.** Add the regression test to the project's existing test file, in its style, covering each case in the list. Run it once and see it fail for the issue's reason; keep that failure line for the report. Then make the minimal correction in the existing idiom. New branches keep the return type and shape, argument validation and input normalisation of the code path they extend (a scalar result stays a scalar, documented contracts hold). When a cheap oracle exists (brute force, round-trip, reference implementation), sweep a bounded input range under a timeout. No changelog or news entry unless the request asks for one.
5. **Contract sweep.** Re-read the issue, then run one probe script (under `TASK/.veera-artifacts/`, with the check's prefix) that exercises every case in the list and prints each result. A missing or wrong case widens the fix: add a file outside scope with `correct-contract --root TASK --reason WHY --add-scope PATH` and the owner options (at most two corrections per run; on this lane the hook's out-of-scope refusal points here, not to a committee), then fix it and test it.
6. **Close in one call.** Read your diff once against each criterion: minimal, every listed case covered, no debug leftovers, no unrelated edits. Then `verify-local --root TASK --notes "C1 plain words on what the diff does and which test proves it"` with the owner options of the CLI form below; keep notes free of `<`, `>`, `|`, `&`, `;`, `$` and backticks. It runs every frozen check on the final tree, records an honest coordinator self-review (not independent), finishes `verified-local` and releases this chat's binding. On `failed` read its `log_tail`, call `repair --reason NEW_EVIDENCE`, correct the source and call `verify-local` again; at most three repairs, unchanged retries are refused. A `defective_check` field, or a log showing the check imports the original checkout, means a defective check, not a defective fix: write `{"checks": [SPEC]}` with the same ID and kind, run `correct-contract --root TASK --reason EVIDENCE --file FILE`, then `verify-local` again. No repair is spent and the run never stops for it; never weaken what the check proves, and a passing check cannot be replaced.
7. **Report** the confirmed cause, the change (TASK path and `veera/SLUG` branch), fail-before and pass-after evidence, check counts and exits, any contract corrections, and "verified locally; unpublished; self-reviewed on the small lane". Name the ceremony skipped.

Unattended means nobody answers: never ask or wait. Take the evidence-backed default, record it as an assumption and continue. This lane uses no dashboard, interview, consultation, independent review, subagent, model router or memory steward; those belong to the standard lane. Never push, publish, release or bump a version, and never change shared repository state (branches, ignore files, Git config, other worktrees) to satisfy a precondition. If `workspace` refuses for a reason outside the defect, do not retry it unchanged or work around it: the session stays unbound, so make the same minimal fix and regression test in the original checkout, run the focused tests and report "not Veera-verified" with the exact refusal. If a bound session's tools are refused inside the task worktree for a reason other than frozen scope (step 5), stop and report the exact hook message instead of probing other tools.

## Standard lane: diagnose and freeze

Read `${CLAUDE_PLUGIN_ROOT}/docs/agent-contract.md` Operating core, then Authority and ownership, Session isolation, Bounded contract, Runtime interface and Evidence and immutable DONE; UI acceptance for UI defects; Selective reasoning, context and repair before delegation or repair. Read `${CLAUDE_PLUGIN_ROOT}/docs/engineering-standards.md` sections Applicability and authority, Role routing and Verification and evidence (reproduce first), then sections relevant to the defect. Read `${CLAUDE_PLUGIN_ROOT}/docs/requirements-analysis.md` and `${CLAUDE_PLUGIN_ROOT}/docs/intake-and-autonomy.md` before planning. Native/project instructions, permissions and stricter recovery ceilings remain binding.

1. Run proportionate discovery: resolve the original Git root, CLAUDE.md/AGENTS.md, relevant code and checks. Clarify only consequential gaps in one initial interview (two or three options, a recommendation, room for a custom answer); never infer an answer from silence and never interview mid-implementation. Freeze `contract.discovery` and `contract.intake` with no open questions.
2. Record start time, a task-derived soft target and an authorized hard ceiling covering diagnosis, review and release. Require a clean committed original root, then `workspace`; use its TASK root and owner file, never the original checkout. Shared worktree metadata and a narrow lock are inherent, not authority over shared ignores/config or peers.
3. Establish expected versus observed behaviour, exact reproduction, impact map and the smallest causal path. Missing credentials or a denial is a blocker, not a bypass opportunity. For UI defects view actual references and define affected states with required rendered/browser evidence.
4. The coordinator owns PM responsibility. Material scope/budget decisions and soft-target replans require actual Architect impact analysis and Advisor alternatives before the PM decision (`decision --root TASK --file DECISION.json`); no invented consultation or routine committee.
5. Write and read back the Bounded contract under TASK's `.veera-artifacts/`: frozen scope, criteria/check IDs, inspected argv/kind/count regex/timeouts, non-goals, UI references, repair ceiling and `release` (`origin`, `main`, one version file, `push_authorized: true` only with user authority; omit it in local-verify). Never hide bookkeeping via shared ignore/config edits. Lock regression checks before remediation. Run `doctor`, then init once.

Only the coordinator owner runs the CLI; never delegate the capability. Required forms (quote actual values):

```text
PY "PKG/scripts/delivery.py" doctor
PY "PKG/scripts/delivery.py" workspace --root ORIGINAL --task SLUG --session-id ACTUAL_HOST_ID
PY "PKG/scripts/delivery.py" SUBCOMMAND --root TASK --session-id ACTUAL_HOST_ID --capability-file OWNER_FILE [ARGS]
```

For `init` add `--mode fix --request TEXT --contract CONTRACT.json --minutes TARGET --hard-minutes HARD_ALLOWANCE`. Unbound hooks no-op; bound wrong-cwd or nested-repository calls block. Before init the bound owner may read its task/plugin docs and write only draft `.veera-artifacts/`, never source. No unrelated ListAgents/SendMessage use, recursive delegation, schedulers or permission bypasses.

## Standard lane: remediate, prove, review

1. After init follow `${CLAUDE_PLUGIN_ROOT}/docs/dashboard.md` (one owned background `dashboard`; report the actual URL). Record phases `discover`, `plan`, `implement` with `phase --root TASK --name NAME`. Use `context --root TASK` for the shared brief; the actual `memory-steward` proposes memory updates imported with `context-import`.
2. Add focused regression tests and minimally correct the confirmed defect in TASK. No adjacent refactors, dependency installs or shared runtime changes without authority. Check `status` before costly work; soft expiry means replan, not stop.
3. Preserve the pre-fix regression failure when practical. In publishing mode call `release-prepare --root TASK` before final verification (integrates `origin/main` in TASK only and patch-bumps the declared version). Record phase `verify` and run every `check --root TASK --id ID`; zero tests, stale or synthetic output do not prove the fix; UI needs real screenshots and interaction.
4. Record phase `review`; an actual independent reviewer checks frozen criteria, causal evidence, diff and check output at the same fingerprint; import with `review --root TASK --file REVIEW.json`. Track blockers with `blocker --root TASK --file OP` and call `repair` before corrective edits: three attempts per blocker and three global repairs by default; denial or human-only issues block at once; at exhaustion obtain Advisor+Architect consultation and a PM decision, never reset counters.
5. `finish --root TASK` needs no unresolved blockers and fresh checks and review (`verify-local --root TASK --file REVIEW.json` runs verify, review and finish in one call for local-verify). Local finish ends `verified-local`; publishing finish records `ready`, then `publish --root TASK` makes at most one plain non-force push to `origin/main` after confirming the reviewed base. Never detach, stash, merge, reset or update-ref peers; a checked-out main blocks publish. Successful completion releases only this chat's binding; failed or ambiguous pushes are never retried automatically.
6. At hard expiry, user stop, denial or exhausted repairs call `stop` and `checkpoint` with `--reason`; `resume --root TASK --file REPORT.json` needs the checkpoint ID, actual user authorization and a `time_plan` totalling the extra minutes. Never reinit.

Return the confirmed cause or remaining hypothesis, scoped correction, actual check counts and exits, UI status, reviewer identity, version/release and push status, gaps and runtime state. A patch or `ready` result is not complete delivery.
