## Fix method

A change without a reproduced failure is a guess; a claim without a recorded result is not evidence.

1. **Baseline once.** Run the project's existing test command once and keep its counts and failures under `.veera-artifacts/`. A green suite shows only what the tests cover; it does not clear the defect.
2. **Inventory defects.** Start from reported failures or symptoms. When no failure list is given, the specification and project documentation are the oracle: read them once into a numbered rule table (inputs and validation, status/error codes, limits, ordering, authorization and tenancy, concurrency, idempotency, time and expiry, pagination, persistence, audit), noting for each rule the enforcing code and the covering test. An uncovered rule or code that disagrees with the text is a suspect. Comments, names and markers are leads, not evidence. The specification bounds the search; this is not a code-quality audit.
3. **Reproduce.** Probe each suspect with the smallest executable check in the project's own test idiom against unchanged source. Before init draft probes only under `.veera-artifacts/probes/`, run them together in one invocation under the native permission policy and keep the output; probe runs must not write elsewhere in TASK. A probe failing on the rule's violation confirms a defect; a passing probe clears the suspect.
4. **Root cause.** Trace each confirmed failure backward to where the wrong value, state or ordering originates and name the violated invariant ("X causes it because evidence Y"). Test one hypothesis at a time; a disproved hypothesis gets a new one, never a stacked edit. Search the same pattern (shared helper, copied handler, same check order) and probe siblings inside the authorized scope. Fix at the source, not the symptom.
5. **Freeze.** Each confirmed defect becomes a criterion (rule ID, expected versus observed, probe output path, impact) with a focused regression check covering its failure states; add the project's full test command as a no-regression check when proportionate. Unconfirmed suspects are reported as hypotheses, not edited.
6. **Red, then green.** In `implement`, move each probe into in-scope test files and run it on the unfixed code: it must fail for the stated reason, not a typo or setup error. Keep that output; when a red run is impractical, say so in the report. Make the smallest root-cause correction, rerun the regression to pass, then the full suite. A miss returns to step 4 with the new evidence. After a hypothesis repeats or three distinct fixes miss the same failure, stop guessing and take the evidence to Advisor/Architect through the Bounded blocker protocol.
7. **Verify once.** Enter `verify` only after every frozen argv already passes in the native shell. A failed controller `check` cannot rerun until `repair` with a new reason, which spends one of the bounded global repairs. A check fails if the run changes the tree ("repository changed during check"): route test output to OS temp or ignored paths outside scope before lock. The count regex must match the runner's own summary; all matches are summed and zero fails.

## Diagnose, remediate and prove

Before the steps below, choose the authorized delivery mode in the draft contract. Select publishing only when the user requested it; publishing requires the version/release prerequisites. Otherwise, and for an explicitly nonpublishing task, freeze `delivery_mode: "local-verify"` and omit `release` before init; release/version requirements below apply only to publishing. No mode changes after init.

1. Run `workspace` first and do all discovery in TASK. Complete the discovery/interview below with Fix method steps 1–5 before freezing the plan. Record original start, task-derived soft target and authorized hard ceiling based on the work items and their estimates including diagnosis/review/release, respecting stricter limits. Inspect project instructions and cheap prerequisites; missing credentials/permissions block, never justify a bypass.
2. Freeze the confirmed defects as criteria with focused regression checks before editing, including affected UI/browser evidence, non-goals, repair ceiling and single authorized release version file. Use the exact shared Bounded contract shape and inspected argv/count parsing; write/read back the task-local draft. Missing release or repository prerequisites block complete delivery. Run doctor and init once with workspace metadata and `--mode fix --request TEXT --contract CONTRACT.json --minutes TARGET --hard-minutes HARD_ALLOWANCE`, preserving elapsed diagnosis.
3. Record discover/plan/implement phases one step at a time. In implement apply Fix method step 6 in TASK without adjacent rewrites; preserve the pre-fix regression failure when practical and state its absence otherwise. Coordinator alone routes actual triggered specialists and owns PM. Use the shared context/provenance and bounded blocker protocols, not invented identities, simulated consultation or a second context store. Soft expiry requires actual Architect/Advisor consultation and recorded PM replan, not abandoned acceptance. Hard limits, denial and exhausted repairs remain binding.
4. For publishing, use release-prepare in implement before final checks; local-verify skips all release operations. In either mode enter verify only per Fix method step 7 and run every frozen selection on the final fingerprint, keeping actual invocations, counts, outputs and required rendered/browser evidence. Obtain actual independent review of the same tree, causal evidence and original check artifacts; read/import its attestation. Static-only/zero-test/stale/synthetic output and self-review do not prove the fix. A failed check or review goes through the bounded blocker protocol, then `repair` with a new reason, which returns to implement and clears review. Observe shared bounded repairs/attempts; no retry around denial or acceptance weakening.
5. Publishing finish means ready, not DONE. Publish only the authorized verified tree through at most one plain non-force push, retaining all release checks. The successful publish result is the completion receipt. For local verification, finish returns verified-local; report "verified locally; unpublished". On either successful terminal result the CLI automatically releases this chat's binding while preserving worktree, state and evidence. Do not issue another status/unbind command after session_binding is released. If cleanup-required is returned, retry only owner unbind after resolving that cleanup error; never rerun publication. Failed, stopped or budget-exhausted tasks keep their binding and checkpoint for recovery.

Native tools follow the existing host permission policy. Veera does not require an extra approval prompt on Codex or reject unfamiliar tool names merely because it cannot classify them. Ownership/terminal checks and supported direct-patch scope checks remain. Shells and opaque tools are governed by native permissions and task instructions, not a claimed Veera sandbox. Actual host denials remain binding; do not evade them.

Return each defect's confirmed cause (or remaining hypothesis) with its rule ID, scoped remedy, red and green regression outputs (or why red was impractical), actual check counts, UI evidence, real reviewer identity, version/release/push state and outstanding criteria/checkpoints. No installation, smoke success or unmeasured savings claims.
